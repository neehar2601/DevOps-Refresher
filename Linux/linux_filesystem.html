The Hierarchy

In Linux, everything lives in one big tree that starts at / (the root directory) and then branches into standard folders with well-defined purposes.

Linux is case-sensitive. Uppercase and lowercase letters in filenames and directory names are treated as completely distinct. /boot, /Boot, and /BOOT are three entirely separate directories as far as Linux is concerned.

Top-Level Directories (FHS)

🌳

/ (root)

The top of the filesystem hierarchy. Every file and directory is somewhere under /; there are no C: or D: drives. The directories directly under / contain only what is strictly necessary to boot the system and perform basic recovery tasks — the minimum needed before anything else is loaded. Think of these as the tools a technician would need if the system were damaged and they had to repair it from scratch.

🧰

/bin & /sbin

/bin: Essential user binaries (ls, cp).
/sbin: System administration binaries (mount).
/lib: Essential shared libraries for these.

⚙️

/etc & /boot

/etc: System configuration files (fstab, passwd).
/boot: Files required for booting (kernel, GRUB).

👤

/home & /root

/home: Home directories for normal users.
/root: Home directory of the root user (kept separate).

📦

/usr & /opt

/usr: Installed applications and shared data (/usr/bin).
/opt: Optional or third‑party software.

🔄

/var, /tmp, /run

/var: Variable data like logs (/var/log).
/tmp: Temporary files.
/run: Runtime state (PIDs, sockets).

💾

/dev & /media

/dev: Device files (/dev/sda, /dev/null).
/media & /mnt: Mount points for removable media.

🧠

/proc & /sys

Virtual filesystems exposing kernel and process information.
/proc: Process info (e.g. /proc/cpuinfo).

Navigating Paths

Every file and directory can be referenced by a path. Understanding the difference between absolute and relative paths is crucial for command-line navigation.

Absolute Paths

An absolute path is the full path from the root directory all the way to the target. It always starts with a forward slash /.

/home/shad/desktop/some.txt

Tip: Use the pwd command to print your current absolute path. In graphical file browsers, the root directory is often labeled as "Computer".

Relative Paths

A relative path is relative to your current working directory. It never starts with a slash.

  • .. — Moves up one level to the parent directory.
  • ~ — Shortcut for your home directory.
  • ./ — Used to execute a script in the current directory (e.g., ./script.sh).

Tab Completion: While typing a path, hit the Tab key. Linux will auto-complete the path if it's unique, or list possibilities if you press it twice. This is essential for speed and avoiding typos!

File Naming & Extensions

Naming conventions in Linux are highly flexible but follow best practices to avoid command-line friction.

Naming Rules

  • Names can be up to 255 characters long.
  • The forward slash / is reserved and cannot be used.
  • You cannot name a file exactly . or ...

Extensions

Extensions (like .txt) aren't strictly required by the Linux kernel, but they help GUI applications determine which program should open the file by default.

Best Practices

Keep filenames short and avoid spaces. If a filename has spaces, you must escape them with a backslash (\ ) in the terminal:

touch audit\ file.txt

Instead of spaces, it is standard convention to use:

  • Underscores: Audit_File.txt
  • Hyphens: audit-file.txt
  • CamelCase: AuditFile.txt

💡 How to make this "click" in practice

Next time you run a program, mentally trace where things live:

  • The binary comes from /bin or /usr/bin.
  • It loads libraries from /lib or /usr/lib.
  • It reads system configs from /etc.
  • It writes logs to /var/log.
  • It uses /tmp for temporary data.
  • The kernel surfaces info via /proc and /sys.

Storage: Physical vs Logical

It is essential to distinguish between the physical storage (the hardware) and logical organisation (the software). This is often described as the difference between the physical "container" and the logical "method" of storage.

1. Partition — The Container

Imagine your hard drive as a physical office building. A partition is a dedicated subsection of that physical media — like a specific floor or suite. It defines a fixed area managed as a single unit. In Linux, partitions appear as device files:

/dev/sda1 /dev/sdb2 /dev/nvme0n1p1

2. Filesystem — The Method

If the partition is the empty office suite, the filesystem is the filing cabinets and indexing system. Without it, a partition is just raw ones and zeros. Formatting a partition installs a filesystem to organise that space:

ext4 XFS Btrfs FAT32

3. Mounting — The Bridge

Mounting attaches a partition's filesystem to a directory (a mount point) in the tree. There are no drive letters — you "attach" storage to a path:

/dev/sdb1 → /home
/dev/sdc1 → /var/log

Note: Generally a filesystem resides within a single partition. However, in some circumstances a filesystem can span more than one partition using symbolic links — a topic covered later in this course.

Partitions

A partition is a section of the hard disk that logically acts as a separate disk. Partitions enable you to convert a large hard disk into smaller, manageable chunks.

  • Must be formatted and assigned a filesystem before storing data.
  • Identified using a partition table in the boot record.
  • Maximum of four primary partitions per table.

Disk Partitioning

Separates system files from user files. Corrupted partitions do not affect others and can be recovered separately.

  • Primary: Contains one filesystem (max 4 per disk). Boot and swap are normally here.
  • Extended: Can contain several logical filesystems. Only 1 extended partition allowed.
  • Logical: Created within an extended partition. No strict restriction, but limit to 12.

Swap Space & Partitions

Swap space is an area on the hard disk used as virtual memory when the system runs out of physical memory (RAM). Unused files are pushed from RAM to swap to free up space. Usually, swap space is twice the RAM capacity.

Types of Swap

  • Device Swap: Configured during partitioning; used to run large applications.
  • Filesystem Swap: Configured on install; emergency resource when swap runs out.
  • Pseudo-swap: Allows large apps to run on limited RAM computers.

Partitions vs Files

A swap partition is a dedicated area of virtual memory on disk. Linux prefers partitions because they perform better.

A swap file is a dynamic file used to transfer data from RAM to disk when a dedicated partition isn't available or is full.

File Systems

A file system provides a structured method for an OS to store, retrieve, organize, and manage files. It maintains metadata like creation dates, sizes, and permissions.

File System Labels

Labels (up to 16 characters) are assigned for easy identification.

e2label /dev/sda1 mylabel tune2fs -L mylabel /dev/sda1

Linux File System Types

ext4

Newest default file system for many distros. Supports journaling, volumes up to 1 EiB, and files up to 16 TiB.

XFS

64-bit, high-performance journaling file system for fast recovery and large files. Default for CentOS/RHEL 7.

btrfs

Modern Copy-on-Write (CoW) focusing on fault tolerance, repair, and easy administration.

ext3 / ext2

Legacy native file systems. Ext3 introduced journaling for data integrity over Ext2.

ReiserFS / JFS

Alternative journaling systems. ReiserFS is highly efficient with small files.

swap

Not a true FS, but disk space used as virtual memory when physical RAM runs out.

Access to Other File Systems

FAT / vfat

Compatible with Windows and MS-DOS. Often used for flash drives.

NTFS

Windows default FS with security, encryption, and large drive support.

ISO 9660

Standard for CD/DVDs (CDFS).

Mount Points & The mount Command

A mount point is typically an empty directory on which a filesystem is loaded (mounted) to make it accessible to users. In Linux, a file system cannot be accessed directly; it must be associated with a directory using the mount command, and disassociated using umount.

The lsblk Command

While fdisk is powerful for creating and modifying partitions, it can be a bit heavy to read. For a much cleaner, tree-like view of how your disks, partitions, and mount points connect together, DevOps engineers usually prefer a command called lsblk.

Journaling File Systems

A journaling file system helps an OS quickly recover after a system crash, often removing the need for a file system check at boot. Instead of writing modified files directly to disk, a journal is maintained:

  • The journal describes all changes to be made.
  • A background process applies each change entered in the journal.
  • If the system crashes, pending changes are performed on reboot.
  • Incomplete journal entries are simply discarded.

Performance Issues

Journaling works well with small files and small drives. However, performance can suffer as drive size grows due to: filesystem recovery time after a crash, the bitmap tracking method, and wasted space/fragmentation.

Integrity & Repair

Use these commands to check and repair file system integrity after hardware failures or improper shutdowns. Note: Always unmount before checking!

  • fsck - Checks integrity. Syntax: fsck -t {type} [options]. Similar to DOS chkdsk.
    To repair a single filesystem: fsck -r /dev/{fs}
  • e2fsck - Specifically checks ext2, ext3, and ext4 filesystems.
    Syntax: e2fsck /dev/{fs}
  • xfs_repair - Specifically checks and repairs XFS filesystems.
    Syntax: xfs_repair [options] /dev/{fs}
