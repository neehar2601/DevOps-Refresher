The Hierarchy

In Linux, everything lives in one big tree that starts at / (the root directory) and then branches into standard folders with well-defined purposes.

Storage: Physical vs Logical

It is essential to distinguish between the physical storage (the hardware) and logical organisation (the software). This is often described as the difference between the physical "container" and the logical "method" of storage.

1. Partition — The Container

Imagine your hard drive as a physical office building. A partition is a dedicated subsection of that physical media — like a specific floor or suite. It defines a fixed area managed as a single unit. In Linux, partitions appear as device files:

/dev/sda1 /dev/sdb2 /dev/nvme0n1p1

2. Filesystem — The Method

If the partition is the empty office suite, the filesystem is the filing cabinets and indexing system. Without it, a partition is just raw ones and zeros. Formatting a partition installs a filesystem to organise that space:

ext4 XFS Btrfs FAT32

3. Mounting — The Bridge

Mounting attaches a partition's filesystem to a directory (a mount point) in the tree. There are no drive letters — you "attach" storage to a path:

/dev/sdb1 → /home
/dev/sdc1 → /var/log

Note: Generally a filesystem resides within a single partition. However, in some circumstances a filesystem can span more than one partition using symbolic links — a topic covered later in this course.

Result New drive letter appears Directory becomes the partition's root

Linux is case-sensitive. Uppercase and lowercase letters in filenames and directory names are treated as completely distinct. /boot, /Boot, and /BOOT are three entirely separate directories as far as Linux is concerned.

Top-Level Directories (FHS)

🌳

/ (root)

The top of the filesystem hierarchy. Every file and directory is somewhere under /; there are no C: or D: drives. The directories directly under / contain only what is strictly necessary to boot the system and perform basic recovery tasks — the minimum needed before anything else is loaded. Think of these as the tools a technician would need if the system were damaged and they had to repair it from scratch.

🧰

/bin & /sbin

/bin: Essential user binaries (ls, cp).
/sbin: System administration binaries (mount).
/lib: Essential shared libraries for these.

⚙️

/etc & /boot

/etc: System configuration files (fstab, passwd).
/boot: Files required for booting (kernel, GRUB).

👤

/home & /root

/home: Home directories for normal users.
/root: Home directory of the root user (kept separate).

📦

/usr & /opt

/usr: Installed applications and shared data (/usr/bin).
/opt: Optional or third‑party software.

🔄

/var, /tmp, /run

/var: Variable data like logs (/var/log).
/tmp: Temporary files.
/run: Runtime state (PIDs, sockets).

💾

/dev & /media

/dev: Device files (/dev/sda, /dev/null).
/media & /mnt: Mount points for removable media.

🧠

/proc & /sys

Virtual filesystems exposing kernel and process information.
/proc: Process info (e.g. /proc/cpuinfo).

💡 How to make this "click" in practice

Next time you run a program, mentally trace where things live:

  • The binary comes from /bin or /usr/bin.
  • It loads libraries from /lib or /usr/lib.
  • It reads system configs from /etc.
  • It writes logs to /var/log.
  • It uses /tmp for temporary data.
  • The kernel surfaces info via /proc and /sys.
